# 0004 — Passive rate-limit headers are an opportunistic merge, never a source

`after_provider_response` carries only `{status, headers}` with no request identity, and Pi's default transport for `openai-codex` is WebSocket-first, where that event never fires at all. Therefore header data is merged into an existing snapshot only: per-bucket, field-wise (present fields win), only when a snapshot exists, only for `x-codex-*` families, and it never extends snapshot freshness — freshness always tracks the last API fetch. The extension never treats headers as a primary source, and a response with no recognizable family is ignored. This keeps the passive path free of cross-account contamination while preserving its only real value: slightly fresher numbers right after a real request.
