# 0003 — One data source: Pi auth + `GET /wham/usage`

All usage data comes from the same authenticated `GET /wham/usage` the official Codex client makes, using Pi's own `openai-codex` credential (Pi does OAuth refresh; the extension never refreshes or writes credentials). The Codex CLI app-server is not used: it adds a process/JSON-RPC dependency, and its auth comes from the Codex CLI session, which may belong to a different account than Pi's, so its data could silently describe the wrong account. A probe request (`POST /codex/responses` minimal request to read limit headers) is also not used: it consumes real quota and adds nothing over the payload endpoint. If Pi auth is absent the extension shows `n/a` — that is the correct state for an extension whose premise is Pi being the provider.
