# 0001 — Reset credits are displayed and consumable, with a guard stack

The extension surfaces usage-limit reset credits (count, option list, expiry) and lets the user consume one. This is the only operation in the extension that mutates the real account, so it ships behind five checks: (1) the runtime token's JWT account id must match the stored credential's account id; (2) exactly one such credential may match, otherwise the flow fails closed; (3) every attempt uses a fresh `redeem_request_id`; (4) the user confirms against a rendered option (title, description, expiry) before POSTing; (5) the outcome (`reset` / `nothing_to_reset` / `no_credit` / `already_redeemed`, `windows_reset`) is explained and the snapshot is refetched. Read-only display was the rejected alternative: the cost of a wasted reset is bounded (no funds, no security exposure, count is visible before acting), while a view-only extension would omit the feature users of the official tools and competitors already expect.
